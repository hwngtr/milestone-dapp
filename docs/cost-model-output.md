## One campaign: 40 donors x $50, 3 milestones

Raised: **$2,000**

| Design | L1 total | L1 % of raised | L2 total | L2 % of raised | Gas |
|---|---:|---:|---:|---:|---:|
| A. Per-donor vote on every milestone | $256.20 | 12.81% | $1.28 | 0.064% | 8,540,000 |
| B. Optimistic release + objection window | $79.80 | 3.99% | $0.399 | 0.020% | 2,660,000 |
| Central database (no trust guarantee) | $0.0009 | 0.000% | - | - | - |
| Card processing for the same money | $75.00 | 3.75% | - | - | - |

Design A costs **$176.40 more on L1** for the same campaign.
The naive design spends 69% of the total on
donors confirming that work they can already see was delivered.

Design B is the one implemented. A donor pays nothing in the happy
path. The objection path costs one transaction, and it is paid only by
donors who believe the release is wrong.

### Reading

On L1 the transaction cost is the same order of magnitude as card fees,
so L1 does not win on price. On an L2 both designs are roughly two
orders of magnitude cheaper than card processing, which is the only
economic argument that makes a per-donation on-chain flow defensible.
This is why the design targets an L2 testnet and measures L1 as the
comparison baseline.

## Throughput sanity check (Design B)

| Quantity | Value |
|---|---:|
| Transactions per campaign (create + contributions + delivery + release) | 47 |
| L1 gas per campaign | 2,660,000 |
| Campaigns per L1 block at 30M gas (theoretical, all gas to this app) | 11 |
| Campaigns per second on L1 (12 s blocks, theoretical maximum) | 0.94 |

One campaign uses 8.9% of an L1 block, so at most about
11 campaigns fit in a block, or 0.94 per second with
every block devoted to this application. That ceiling is the strongest
argument against L1 at scale, and it belongs next to the cost table.
